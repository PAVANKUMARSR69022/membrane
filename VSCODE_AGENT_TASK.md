# VS Code Coding Agent — scoped instructions

You are helping implement the Membrane Robot Hackathon system from the supplied official brief.

## First task: audit, do not rewrite
1. Read `README.md`, `engine/config.py`, `engine/world.py`, `engine/simulation.py`, `engine/server.py`, and `agent/`.
2. Identify correctness bugs, especially PyBullet API usage, coordinate conventions, camera pose, collision handling, object attachment, and whether the server can run reliably.
3. Do not change files until you report the issues and propose a small ordered fix list.

## Non-negotiable competition constraints
- Engine owns all object truth.
- Agent/Claude may receive only robot state (state, x/y, heading, holding, retry count), camera JPEG, optional single-ray depth, collision flag, and tool results allowed by the brief.
- Never expose object names, IDs, colours, shapes, positions, counts, target distances, segmentation masks, or drop-zone coordinates to Claude.
- `/pickup` must return success/failure only; it must not identify the picked object.
- `/drop` may report whether the object landed in the drop zone.
- Claude must receive actual image content, not a text caption generated by the engine.
- One Claude call and exactly one tool call per step once the agent is implemented.
- One `/look` after each `/move` or `/turn`; do not send two consecutive images without movement/turn between them.
- Scene time is paused while Claude is thinking; advance simulation only during move/turn.
- Log each step as JSONL: step, timestamp, tool, args, result, frame_path. Save frames as PNG.
- Collision stops movement, backs off 0.1m, returns collided=true, enters Blocked. Retry after backoff/turn; fail after 3 retries.
- Use metres and degrees. Heading 0 is +x; positive heading is clockwise viewed from above. Positive turn is right.
- Camera: 640x480 JPEG, 90-degree horizontal FOV, 0.5m above floor, tilted 10 degrees down.
- Movement speed 1m/s; turn speed 90 degrees/s; pickup reach 0.5m and within ±30 degrees.
- Do not add dashboard/UI features unless needed for the required demo.

## Development workflow
- Work in small changes.
- Run syntax checks and tests after each change.
- Preserve working code; do not rewrite the entire project.
- Explain changed files and commands to run.
- Do not invent the organizer's Claude model ID, API base URL, token format, or feedback API schema.
- Do not call the Claude API until the organizer-provided credentials and exact model identifier are available.
- Prefer Python 3.11 compatibility.
